# 下一阶段讨论稿：本地图库与导航

状态：存储方向已确认，后端尚未实现。软件管理磁盘上的资产文件夹，照片以原始文件形式独立存放，其他元数据使用数据库；未来可配置目标路径。

## 最小可用闭环

创建/打开图库 → 导入 → 预览 → 标记多人/日期 → 关联已有收藏 → 重启后恢复。
前端通过 Tauri command 调用 Rust；Rust 负责图库权限边界、数据库、文件复制和预览任务。数据库使用 SQLite，图片不放数据库。

建议的托管目录：

```text
library/
  library.sqlite
  originals/<asset-id>/<rendition-id>.<ext>
  previews/<asset-id>/<rendition-id>.jpg
  thumbnails/<asset-id>/<rendition-id>.jpg
  staging/<import-job-id>/
  trash/
```

原件不可覆盖，保留来源文件名，使用相对路径以支持整体移动。应用私有设置保存最近打开图库的位置。仅引用原文件的模式需要另行处理路径失效和文件外部修改，不能静默当作托管复制。

## 数据与恢复

沿用 Cheki / Asset / Rendition，以 ChekiAsset 处理多对多，ChekiPerson 管理多人。封面可指向影像并保留非破坏性裁切区域。日期允许未知，收藏日期与影像成像时间分开。

导入先写 staging，流式复制并计算校验和，完成后迁移到最终路径并提交索引。数据库与文件系统不是同一个原子事务，使用导入任务状态记录实现中断恢复与孤立文件清理。哈希相同只表示文件重复，不用于自动判定同一件实体收藏。UI 显示进度和可重试失败。

预览生成在后台任务中执行，限制并发，逐文件处理；需要对大 TIFF 验证解码内存上限。原件入库成功与预览生成成功分开记录。图片不会以 base64 经 IPC 整体传输给前端。

图库级删除进入回收站；共享 Asset 仍有关联时不得删除其文件。备份必须同时包含一致的 SQLite 快照和原件，不能只复制运行中的数据库主文件。

## 导航提案

路由与视觉主次分开：有独立 URL 不意味着必须占据主导航。

- `/`：全览；搜索/人物/待整理等条件放查询参数。
- `/cheki/[id]`：收藏详情，可直接访问。相册内打开时保留模糊背景；直接进入时独立加载，不依赖上一页内存。
- `/people`：若仅用于筛选，先做弹出选择器；若需要人物管理再做列表页。
- `/people/[id]`：仅在需要人物资料时加入；照片浏览复用相册。
- `/settings`：次级页面，包含图库位置、预览策略等。
- 统计：待明确需要的指标及相应数据后再实现。

关闭详情或从次级页返回应恢复搜索、筛选和滚动位置；浮动工具条中的应用菜单提供低频入口。第一阶段不加入同级页面标签栏。
